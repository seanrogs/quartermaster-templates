# N26 Review Notes

Running log of judgment calls made while building N26 gang files from screenshots, for manual review/correction. Each entry: what was assumed, and why. Newest entries at the bottom of each section.

**Standing rule (corrected 2026-08-12):** every Pet-type fighter attaches to every other fighter in the gang, the same way Cawdor's Sheen Bird does — regardless of whether the rulebook gives it its own priced card. Delaque and Escher were both built wrong at first (pets as standalone Fighter-role roster entries) and have since been fixed; `build-gang-template`'s SKILL.md now states this as the rule going forward.

**Standing rule (corrected 2026-08-13, from user review of Cawdor):** a zero `Points` value must be `<real>0.0</real>`, never bare `0` — confirmed as what the Quartermaster app itself writes. Swept and fixed across every file (`N26.qmsystem`, all six gang files) — see the `git diff` from this pass if the exact fixed lines matter. Restriction lists belong in `Prerequisite`, never crammed into the item's `Name` in parentheses (`exterminator (autogun, shotgun, chainaxe and eviscerator only)` → `Name: exterminator`, tag `autogun/shotgun/chainaxe/eviscerator, Redemptionist`). Ammo-type variants always get `Multiple: true` plus a parent-weapon reference in `Prerequisite`, even brand-new ones — Escher's `shotgun acid ammo` was missing `Multiple` and got fixed to match. All three now documented in `build-gang-template`.

**Standing rules (added 2026-08-15, from user review of Cawdor/Delaque/Escher):** `Upper Limit` only on Leaders; a mount that grants its own weapon(s) becomes a per-fighter `Mount` key instead of a plain catalogue purchase (a mount that's just a subtype/movement grant stays a plain catalogue item, updated in place); starting skills/named special rules/fixed equipment that appear on a fighter's card are now captured instead of skipped; Brutes (and any unit whose card says it "may not purchase or be equipped with additional weapons or wargear") lose their `Magic Items` purchase list and their pet `Attached Units`, gaining fixed `Equipment` instead; every gang's Stash needs a `Gang Equipment` allowance; a gang's own name gets title-cased where it appears in an item name. All now documented in `build-gang-template`. Applied to Goliath, Orlock, and Van Saar this pass — Cawdor/Delaque/Escher are the user's own manual edits and weren't touched, see the judgment calls below for a few things noticed in passing there.

**Standing rules (added 2026-08-16, from user's manual edits to Cawdor and Palanite Enforcers):** every fighter with "Specialist" in its Type/Special Rules gets an identical fixed `Specialist` selection block in `Magic` (Heavy/Bulging Biceps, Gunner/Hip-shooting, Gunslinger/Gunfighter, Scout/Clamber, Sniper/Precision Shot, Brawler/Berserker, Medic/Medicate, Tech/Munitioneer) — applied by the user to Cawdor Brethren and Redemptionist Brethren; every Vehicle uses a `Lasting Damage` table instead of `Lasting Injuries` (vehicle-appropriate results, 14 entries not 17 — see `build-gang-template` for the full mapping) — applied by the user to the Tauros Venator, the first Vehicle we've built. Both now documented in `build-gang-template`. The `Specialist` block was retrofitted onto every other gang's Specialist-subtype fighter (Cawdor's own two are the user's manual edit and were left as-is): Delaque Ghost, Escher Gang Sister, Goliath Bruiser, Orlock Gunner, Van Saar Tek, Enforcer Patrol Officer, Enforcer Subjugator Patrol Officer, Corpse Grinder Cult Skinner. `Lasting Damage` not yet retrofitted anywhere else — Palanite's Tauros Venator is still the only Vehicle we've built. Also noticed and fixed in passing: a batch of `<real>0</real>` that should've been `<real>0.0</real>` slipped through in Palanite (the zero-Points rule from 2026-08-13 — worth double-checking new files don't reintroduce this), and inconsistent indentation in Palanite's per-fighter Skills `Magic Items` blocks (tabs vs. mismatched depth) which the user cleaned up manually.

## Indentation bug in the first Alliances pass (fixed)

- **The alliances as first written were misindented by one tab level throughout their `Attached Units`.** Each delegation fighter's `<dict>` was emitted at the same depth as the enclosing `<array>` rather than one level deeper, and everything nested inside inherited the error — 2,177 lines in total. `plutil -lint` passed throughout, because XML does not care about whitespace, so the fault was invisible to the checks being run.
- **It surfaced only when the file was round-tripped through Quartermaster**, which rewrote the whole file correctly and produced a ~2,100-line diff that looked alarming but was almost entirely re-indentation. A depth audit (compare tab count against XML nesting depth) confirms: the committed version had 2,177 misindented lines, the app's output has zero.
- **Lesson for future generated blocks**: `plutil -lint` is not sufficient. When emitting XML by hand, verify that tab depth tracks element nesting — the check is cheap and catches exactly this. The same audit should be run over any other template built by the same generators.
- Quartermaster also normalised one pre-existing inconsistency while it was there: the Magistrate's `Lasting Injuries` options were missing the `Count` key on their 2nd and 3rd entries, which had been noted as a wart in the previous pass.
